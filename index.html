Hog Bank v2.0 Enterprise Core

A full-stack, ACID-compliant banking prototype engineered with C#, ASP.NET Minimal APIs, and SQL Server. Built to intercept threats at the database level and model macroeconomic stress in real-time.

1. System Architecture & The Relational Core

At the heart of Hog Bank is a strictly normalized, ACID-compliant SQL Server database. Rather than relying on the frontend for financial math, the C# ASP.NET backend acts purely as a high-speed routing layer, deferring to secure SQL stored procedures for double-entry ledger settlement.

By enforcing Foreign Key constraints across Customer, Account, and Transaction tables, the system guarantees absolute data integrity. Every dollar moved is permanently traced to a specific teller, terminal, and geospatial coordinate.

2. The Hardened Security Arsenal

Proactive Database Defense

Legacy banks detect fraud after the money is gone. Hog Bank intercepts it mid-transaction.

Idempotency Gateways: Cryptographic cache tokens instantly drop duplicate API requests, neutralizing the risk of double-spending.

Geospatial Intercepts: Using native SQL POINT geometry, the database calculates "Impossible Travel" velocities. If a card is swiped in Fayetteville and Tokyo within 5 minutes, the account is systematically locked before the settlement clears.

3. CRM & System-Versioned Temporal Audits

The "Time Machine" Ledger

Financial institutions are heavily regulated by compliance laws. To meet these standards, our CRM utilizes SQL Temporal Tables.

When a teller updates a customer's profile (like an email address or physical location), the old data is never overwritten. The database automatically versions the row with exact timestamps, creating an immutable, legally compliant audit trail.

4. Algorithmic Underwriting & DFAST Stress Testing

Macroeconomic Scenario Engine

We built a dynamic risk engine that assigns algorithmic interest rates based on 30-day trailing cash flow (the "HogScore").

To prove the robustness of the system, we generated toxic subprime loans and subjected the portfolio to a DFAST (Dodd-Frank Act Stress Test). By simulating Federal Reserve recession shock multipliers against our Net Present Value (NPV), the application dynamically maps the bank's liquidity collapse—and subsequent recovery via Asset-Backed Securitization (ABS) block trades.

5. AML Forensics & B2B Data Ingestion

Graph Theory & Statistical Analysis

To audit millions of synthetic transactions, we implemented statistical forensic tools directly into the executive dashboard.

This includes Benford's Law distribution charts to catch manipulated numerical ledgers, and Graph Theory algorithms (DFS) to map and visually flag circular Anti-Money Laundering (AML) syndicates.
